1 · The big picture

The journey of one prompt

A modern chat or code model is a stack of identical blocks. Text goes in at the bottom, flows up through the stack, and one token’s worth of probabilities comes out at the top. Select a stage — or press Play tour — to light up that part of the machine.

Where this differs from the 2017 paper
  • The original was an encoder + decoder built for translation. GPT-style chat and code models keep only the decoder stack — the one drawn here.
  • Modern models commonly use rotary position embeddings (RoPE) rather than adding sine/cosine waves, and apply LayerNorm before each sub-layer (pre-norm).

2 · From words to numbers

Embeddings + position: what the model actually sees

Each token ID looks up a learned vector. Then a position signal — a pattern of sines and cosines at different speeds, like the hands of a clock — is added to it. Their sum is the input to layer 1. Try shuffling the words and watch which columns change.

negative value positive value colour strength = magnitude · hover a cell for the number

Only d = 6 dimensions are shown (real models use hundreds to thousands). Token vectors here are made-up stand-ins for learned values and the IDs are illustrative; the position pattern uses the paper’s actual sinusoidal formula. Notice the first pair of position columns changes fast from row to row while the last pair barely moves — fast and slow clock hands.

The insight: after shuffling, every token keeps the same embedding but meets a different position pattern, so the sums differ. That is how order enters a network whose attention layers would otherwise see only an unordered set.

3 · The heart of the transformer

Self-attention: every token reads the others

For each token the model builds three vectors from its current representation. The query is compared with every key; the better the match, the more of that token’s value gets blended in. Below, the context is the same prompt the model is about to continue.

QQuery

“What am I looking for?” Made from the token that is currently reading.

KKey

“What do I contain?” Made for every token, so queries have something to match against.

VValue

“What do I hand over if picked?” The content that actually gets mixed into the reader.

Under the hood · reading as it

  1. Score the query against every key (dot product).
  2. Scale by 1/√dk so scores don’t blow up in high dimensions.
  3. Mask the future (set to −∞).
  4. Softmax → weights that sum to 100%.
  5. Blend the values using those weights.

4 · The last step

Predict, sample, append, repeat

The top of the stack yields one score (logit) per vocabulary entry. Softmax turns scores into probabilities; temperature sharpens or flattens them before one token is drawn. That token is appended, and the entire journey runs again for the next one.

What one loop iteration costs
  1. Run the new text through all N blocks (earlier tokens’ keys & values are cached, so mostly only the newest token is computed).
  2. Take the vector at the last position → logits → probabilities.
  3. Sample one token → append → go to step 1.

Logits are hand-written for illustration (top 5 shown; a real model scores the whole vocabulary). The point is the mechanics: nothing here checks whether a continuation is true — only whether it is probable.

5 · Same blueprint, bigger

From 65 million to 175 billion parameters

There is no extra secret ingredient hiding in large models. They repeat the same block — attention, MLP, residuals — with more layers, wider vectors and more heads.

In the base model dmodel = 512 = 8 heads × 64 dims each, and the feed-forward layer is 4× wider (2048). With that 4× width, roughly two-thirds of each block’s weights sit in the MLP (8d²) and one-third in attention (4d²).

6 · Why it matters on the job

What the architecture means for your Copilot habits

Each habit taught in this programme has a mechanical reason behind it.

🎯

Context is an attention budget

Attention weights come from a softmax, so they sum to 100%. Every extra, loosely relevant token competes with the ones that matter — noise dilutes focus.

🎲

Probable is not verified

The final step samples from a distribution. Nothing in the stack checks facts, which is why specs, tests and review sit at the core of this programme.

💸

Long context costs twice

Input and output tokens are both counted, and attention work grows roughly with n². Trimming context saves money and sharpens answers.

🌡️

Temperature only touches the end

It rescales the logits just before softmax; the stack below is unchanged. Low for code and refactors, higher for brainstorming.
