How an LLM really works

It doesn't look things up, and it doesn't reason the way you do. It reads tokens, scores every possible next token, picks one, and goes around again. Prompts, context and agents are all built on that one loop.

    04

    Attention: how a token looks around

    In the transformer layers, each token pulls in information from the tokens before it. Click a word to see where it "looks". The arc thickness is the attention weight.

    Look left, never right. A next-token predictor is trained to guess the next token, so a position may only attend to itself and earlier tokens. The words that come after it do not exist yet.

    Illustrative weights, hand-authored to show the idea. They are not read from a real model. Real models run many attention "heads" in parallel in every layer, each learning a different pattern.

    05

    Where the numbers come from

      The context window is the model's entire memory
      
  
      A fixed token budget is shared by everything the model sees, including the answer it is about to write. The model is stateless between calls, so whatever does not fit is simply gone. Fill the window and watch what falls off.

        08
        Five things to carry into the rest of the course
        
  
        
    
        Probable ≠ correct
        Output is the most plausible continuation, not a verified fact. Fluent code can still be wrong. Specs, tests and review are how you close the gap.
        → M04 · M06 · M08
        
    
        Tokens are the currency
        Input and output both count toward cost, speed and limits. More tokens is not better: extra noise dilutes focus.
        → M11 observability & ROI
        
    
        The window is all it knows
        The model is stateless between calls. If it is not in the window right now, it does not exist for the model.
        → M03 context
        
    
        Context is the lever
        What you put in the window, and how you shape it, moves quality more than a cleverer prompt. If a new teammate couldn't do the task from your prompt, neither can the model.
        → M03 · M04 spec-driven dev
        
    
        Agents are loops
        Plan, act, observe, adjust, with tools and a human checkpoint. No magic, so design the guardrails on purpose.
        → M02 · M07 MCP · M09–10
